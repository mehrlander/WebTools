# HTML house style (portable)

**This is the style guide. Asked for "the style guide", "the HTML style guide",
or "the page style guide", this is the name.** The rules themselves live one file
away, in the skill that fires on page work whether or not anyone asks for them:
[`skills/daisy-alpine/SKILL.md`](../skills/daisy-alpine/SKILL.md). The DaisyUI,
Tailwind and Alpine mechanics are beside it, in
[`skills/daisy-alpine/references/mechanics.md`](../skills/daisy-alpine/references/mechanics.md).

The names are stated here because the file did not carry them and could not be
found by them: searching "style guide" across the estate returned
[google-style-clarity](../skills/google-style-clarity/SKILL.md), which is the
guide for **prose**, and searching "html style" returned nothing, the hyphen in
the filename splitting the phrase. **A document has to be findable by the words
someone who has not read it would use**, which are rarely the words it uses about
itself. That is why this path survives as a pointer rather than being deleted.

## Why the rules moved into the skill (2026-08-31)

This file and the skill each declared a half of one subject, this one "what pages
look like, not how they are built" and the skill "how to build". Measured against
those declarations, neither held: **57% of this file's rules were library
mechanics, and 42% of the skill was house style.** The two had also parted, with
five rules here that the skill lacked and seven shared ones reworded at different
lengths, and nothing held them together. The duplication scan ranked the pair
first in the repository, at 76 shared ten-word windows.

The rules go where they must fire. A session in another repository loads the
skill unprompted on page work and may never fetch a doc; the rules are what has
to be present at that moment, so the skill carries them and the mechanics support
them. The relationship is now the file layout rather than a claim each file makes
about the other.
