# Merge guide

Every merged pull request, newest first: the date, the title, and a link to
the PR, whose body carries the full account of what shipped. This file is the
index; GitHub holds the entries.

It is an index rather than a copy on purpose. A PR's number, title, and merge
date are fixed once it merges, so a line here cannot drift from its subject,
and every merged PR gets one whether or not its body was written to the guide
convention. Copying the bodies in would duplicate what GitHub already renders,
silently drop every PR with a terse body, and carry per-file links that later
renames break. See docs/SURFACING.md, "Merge guide".

Generated by `scripts/build-merge-guide.py --index`; do not hand-edit, except
under the trailing "Merges without a pull request" heading, which is preserved
verbatim. Regenerate:

    python3 scripts/build-merge-guide.py mehrlander/web-tools --index --out docs/MERGE-GUIDE.md

The sandbox proxy 403s `api.github.com`, so in a Claude Code web session feed
it MCP-fetched PRs instead: page `list_pull_requests` (state closed, fields
number/title/merged_at), write the array to a file, and add `--from-json`.
