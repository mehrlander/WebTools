# Snags

Things learned the hard way: small friction you trip over, noted so you trip on
it once, not three times. A triage queue, not just a diary. Each entry is a
one-liner (symptom, then the corrected move) with a `→` to the durable doc that
carries the full fix. Newest on top.

**Recurrence is the signal.** One trip is noise; the same trip two or three
times earns a systematic fix. An entry tracks how often it bit; a snag that
keeps recurring graduates to a [tracker](../tracker/) task that removes the
cause. The log triages, the tracker does the work.

Distinct from the other logs by what it keys on: the tracker keys on a **task**
(intent), a merge guide on a **PR** (delivery), this on a
**snag** (a recurring friction), atomic and cross-PR. Entries stay an index (a
one-liner plus a `→`), so they cannot drift from the docs that hold the fix.

**Counting a repeat is mechanical, as of 2026-08-14.** The index below is
generated by `npm run snags-index` and regenerated by the commit hook whenever
this file changes. The same run prints, to the terminal, any pair of entries
whose slugs share two or more words: the cheapest signal that a new entry is a
repeat of one already here. It fires at commit time, while the entry is being
written and folding it in is still a one-line edit. It is advisory and never
blocks, because overlap is a guess; two unrelated loader snags would both carry
"loader" and be perfectly fine. What prompted it: a session wrote
`headless-prose-unstyled` for a trip `headless-shot-prose-flat` already owned,
and the collision surfaced days later as a merge conflict rather than at the
keystroke.

**Every entry now leads with a slug**, which is what makes the count above
mean anything. Eleven did not until 2026-08-14: the log's older shape was a
bold lead-in with no heading, and thirteen sightings sat in blocks the
recurrence rule could not see, about a third of the log. They were migrated
rather than parsed around, the lead sentence of each becoming its heading and
the rest left word for word. Two of them turned out to be continuations of the
entry above (a dated correction, a corrected move) and were folded into it,
which is where their second date came from.

**That migration was not finished, and the sentence above claimed it was for
twelve days.** Seven entries in the tail kept the retired heading and were
absorbed by the entry preceding them, so `status-audit-skipped-index` read ×8
against a true ×1: seven of its eight sightings belonged to other snags, and
three of those were not dates at all but the words `one text`, `one fill`, `one
straggler`, split out of a sighting list written as prose. An eighth entry sat
at the very bottom as a bold-lead bullet and was a third trip on
`x-data-scope-shadows-component-names`, so it is folded in there now.
Converted 2026-08-26, and both failure modes report instead of absorbing: a
sighting has to be a date (the `×N` multiplier is read), and an unslugged
heading is named at the terminal.

**The mechanical half is a registry**, [`snags.csv`](snags.csv): a row per snag
carrying its slug, one-line title, sightings, count and `→` targets, written by
the same run and held to this file by `tools/test/derived-artifacts.test.mjs`.
The generator was already reading the log as data; the records just did not
survive the run, so nothing could hold the extraction to a schema and no other
surface could read it. The prose stays here, because the paragraph explaining
why a trip was invisible is most of an entry's value and is a poor fit for a
cell. Sort, filter and count in the CSV; learn something in the entry.

like the merge guide, the recurrence mechanism, and the format are open in

### shot-of-a-prebuilt-page-ignores-lib: a break-check that proved nothing
`pages/branch.html` imports `../dist/web-tools.js` rather than running a
`gh.load` chain, so a headless shot of it renders the PRE-BUILD, not `lib/`. A
verification pass that edits a component, shoots the page, and reads an
unchanged measurement has confirmed nothing: the edit was never in the bundle.
It is the dangerous shape again, since the run succeeds and the number is real,
just of the old code. Worse in a break-check than in ordinary work: there the
unchanged number reads as "the class was doing nothing", which is the opposite
of the truth, and the tempting next step is to delete the class. Caught
2026-09-06 on a `-mt-2` that measured as a no-op twice.
The corrected move is `npm run build:lib` in the same command as the edit,
before any shot of a page that imports the pre-build; `grep -n "dist/" <page>`
says which pages those are. Sibling of
`page-skips-the-loader-ignores-use`, and the boundary between them is who is
looking: that one is a READER handed `?use=` by a page that skips the loader,
this one is the SESSION shooting a page that imports the pre-build. Same
sentence either way, "the lib you edited is not the lib on screen", with a
different cause and a different fix. *(seen: 2026-09-06)*
→ [tools/README.md](../tools/README.md#the-pre-build)

### touch-synthesises-a-hover: the same gate, missed on the second of two elements

**Two defects, one panel, found in one sweep**, and the second only after the
first was fixed: the panel had to survive being touched before anything could
test what closed it.

A touch screen synthesises hover events on tap, so any hover-driven open or
close needs `matchMedia('(hover: hover)')` around it. `kits/session-export.js`
learned that once, on the row that TRIGGERS its panel: ungated, the dwell and
the tap both fired and the panel opened and toggled itself shut. The panel's own
`pointerover`/`pointerout` pair, added in the same commit for the grace period
that lets a mouse travel into it, did not get the gate. Reported 2026-09-07 from
the phone as "I tap the popover and it disappears": lifting a finger fires
`pointerout` with a NULL `relatedTarget`, so `peek.contains(e.relatedTarget)` is
false, the leave timer runs, and the panel goes 220ms after being touched.
Measured at 430x932 with hasTouch: open, still open at 50ms, gone by 500. Two
sightings of one cause, in one file, from one commit. The corrected move is that
the gate belongs on every handler in a hover pair, not on the one that opens;
and a coarse pointer keeps the dismissals that are not hovers, which is the
whole set it ever had (close button, Escape, outside pointerdown, second tap). →
**The second is an ordering defect in the same panel's dismissal.** The
component root's capture-phase `pointerdown` ran BEFORE the click that toggles,
so a second tap on the row that opened the panel shut it there, cleared the
`peekAt` the toggle reads, and `showPeek` then saw nothing open and opened it
again. Shut and reopened inside one gesture reads as nothing happening, which
is not what the trigger promises; measured with hasTouch as row 2 staying open
through two taps while row 7 correctly took the panel. It bites a mouse
identically and is invisible there, because the hover that opened the panel is
still holding it. The corrected move is that a dismissal listener must not
reach the open panel's OWN trigger, which leaves every other route as it was.
Both halves are the general shape this file has now hit three times: **two
handlers racing for one gesture.** →
[`lib/kits/session-export.js`](../lib/kits/session-export.js), gated in
`tools/test/session-export-open.test.mjs`, whose harness stubs matchMedia to
`matches: false` and so tests the coarse-pointer path by default.

### boot-throw-hides-behind-x-cloak: a bad `?use=` ref rendered as a broken page, not a bad link

The `?use=` boot script throws a good sentence when the pinned bundle 404s, and
throws it into a console no phone opens. The body carries `x-cloak` and the page
hides a cloaked element outright, so Alpine never starting means the attribute
never comes off: the reader gets a WHITE PAGE. A mistyped ref and a broken page
are then indistinguishable, which is why one handed-over link with an invented

rather than read from `git rev-parse`, which is the first corrected move; the
second is that the failure has to paint. `pages/session.html` now catches, writes
the message and the offending ref into the body with inline styles (the page's
own machinery is what failed, so reporting must not depend on it), and rethrows
so the console keeps the stack. **Five other pages carry the same block
verbatim and are still silent**: `branch.html`, `review.html`, `inquiry.html`,
`demos/prebuild-demo.html`, and `app/index.html` with a variant. Doing it once
rather than six times is the open question, since the reporter cannot live in
the bundle whose absence it reports. →
[`pages/session.html`](../pages/session.html) carries the worked case.

### merge-drops-authored-csv-cells: taking one side of a derived registry loses the authored half, and the generator refills it blank

`docs/tests.csv` carries two kinds of cell: authored (`kind`, `protects`) and
stamped (`assertions`, `runner`, `assertion_names`). Resolving a merge conflict
in it the way the derived half wants, by taking one side and regenerating, is
exactly wrong for the authored half: `git checkout --theirs` drops every
`protects` this branch wrote, and `npm run tests-index` then re-adds those rows
with a BLANK `protects` rather than failing, which is indistinguishable from a
new test nobody has annotated yet (the registry says so on purpose: "a ledger,
not a ban"). Bit twice in one branch, three rows then six. The corrected move is
to restore the authored cells from your own commit before staging,
`git show <sha>:docs/tests.csv`, and to check `protects` for blanks after any
merge that touched the file. The systematic fix is a union merge driver on the
row-per-line registries, so an additive conflict stops being a conflict at all;
not attempted. *(seen: 2026-09-04 ×2)*
→ [tools/README.md, the refresh model](../tools/README.md#the-refresh-model)

### shallow-clone-has-no-merge-base: the render-link script reported "nothing" over a nine-file branch
`scripts/showing.py` reads its input from `git diff --name-only origin/main...HEAD`.
A Claude Code web sandbox clones shallow, so `origin/main` and `HEAD` share no
ancestor inside the graft boundary and the three-dot form dies with
`fatal: no merge base`. `sh()` returns `.stdout.strip()` and never reads the exit
code, so the failure arrives as an empty file list and `pick()` falls through to
its last branch: "No render link: nothing that renders changed." Confident,
plausible, and wrong about a branch that had changed `app/index.html`. The
session believed it and told the user there was no render link. Measured
2026-09-03 on PR #574: `git rev-parse --is-shallow-repository` → `true`,
`git merge-base origin/main HEAD` → empty, `git log --oneline origin/main | wc -l`
→ 170 against a `main` that was really 3 commits back. The corrected move is
`git fetch --unshallow origin` (about 20s) before trusting any `origin/main...HEAD`
read, not the two-dot form, which on a shallow clone compares two grafted tips
and returned 300+ files here. **Third sighting of one shape**, after
`showing-whitelists-pages-only` and `showing-answers-commits-only`: the diff was
wrong or absent and the classifier had no case for it, so per the conventions'
recurrence rule this one earned a fix rather than another entry. **Fixed the same
day:** `sh()` takes `check=True`, the two reads that decide the answer
(`changed`, `diff_text`) ask for it, and a failed read is now its own mechanism,
`unknown`, printing "CANNOT TELL" rather than borrowing the words of "nothing to
show". `diff_remedy` names the shallow case and the command. Held by
`tools/test/showing-pick.test.mjs`, which drives a real orphan-base diff rather
than a file fixture, since every other test there hands the script its input and
would have passed throughout. →
[showing.md](showing.md), and the classifier at [../scripts/showing.py](../scripts/showing.py);
[`skills/sandbox-traps/SKILL.md`](../skills/sandbox-traps/SKILL.md) for the
shallow-clone family this belongs to. *(seen: 2026-09-03)*

### python-offsets-read-as-utf16: an emoji shifts every standoff offset the browser reads
`skills/state-the-rule/segment.py` writes character offsets, because Python
indexes a string by code point. `lib/kits/standoff.js` and the audit page slice
with `String.prototype.slice`, which indexes by UTF-16 code unit, so one astral
character (every emoji in these docs) shifts every later offset by one.
`docs/SURFACING.md` carries 49 of them: a browser slicing at segment.py's
offset for `surfac-023` reads a span starting two characters early, `".\n\n* **Show
pixels.**…"` rather than `"* **Show pixels.**…"`. Nothing has noticed because
the one stored run annotates `docs/CONVENTIONS.md`, which has none. Found by a
corpus test comparing the two implementations, which had to convert the offsets
to compare anything at all. The corrected move is a boundary rather than a new
format: each language stays native inside itself and converts where a number

### nul-byte-truncates-grep: one NUL in a source file bounds every `grep -rn` over it, silently

### guards-shift-the-offsets: three of segment.py's five guards are not length-preserving
